Description

Web Exports are working in 4.3/4.4 though still experimental. Test it here:
https://tokisan.com/terrain3d_demo/demo.html

We have successful reports from:

  • Win11/64, RTX3070
    • Edge 134.0.3124.72, 30-40fps
    • Chrome 134.0.6998.166, 50-75fps
    • Firefox
  • Linux
  • Android
  • MacOS
    • Edge
    • Safari
    • Firefox (textures don't work)+
  • ios+

+7/16/2026 Update: #1003 adds a new feature: Terrain3DMaterial.max_regions limits the number of regions rendered and reduces the uniform buffer consumption which is needed for ios on web, and some androids. Set to the minimum number required, 64-256.

8/12/2026 Update: Nightly builds are now using emscripten 4.0.11, and comes both nothreads and threads, release only, matching what Godot 4.7 provides. Because of the builds and updates now, most of the steps below can be skipped. The process is mainly use compatibility, get your export settings right, upload, and configure your webserver properly.

Further platform support is out of our hands. In order for it to work properly, Texture Arrays and other webgl features need to be fully supported by the hardware/OS/driver/browser/Godot/emscripten. If it doesn't work, we can do nothing. Though you could try importing your textures as vram uncompressed.

Start

Here is the working process so far.

First, the terrain build, the export template, and export settings must match the same thread support with all three threaded or not.

Building

Unthreaded Web builds and terrain.gdextension updates have now been included in the v1.0 release and main nightly builds, so this section can be skipped.

Use 4.3 or higher.

To build the extension for web you must install emscripten, set up the build environment, then build the web assembly version. I installed with scoop, which is how my python is also installed, per the Godot building instructions.

Emscripten seems to be very finicky about versions. Akien reports they are using v3.1.64 for 4.3 stable builds.

To find the current, look in the web build workflow, or search Godot PRs for emscripten for other versions that might work.

$ scoop install emscripten@3.1.64

# then I restarted my terminal to get the updated path to finish installing emscripten

$ emsdk install 3.1.64
$ emsdk activate 3.1.64

# finally setup the build environment
$ source ~/scoop/apps/emscripten/current/emsdk_env.sh

# build
$ scons platform=web target=template_debug threads=no

$ ls project/addons/terrain_3d/bin/*.wasm
project/addons/terrain_3d/bin/libterrain.web.debug.wasm32.wasm

This file needs to be added to terrain.gdextension:

web = "res://addons/terrain_3d/bin/libterrain.web.debug.wasm32.wasm"

or 

web.debug = "res://addons/terrain_3d/bin/libterrain.web.debug.wasm32.wasm"
web.release = "res://addons/terrain_3d/bin/libterrain.web.release.wasm32.wasm"

Untested possibilities:
web.wasm32.nothreads = "res://addons/terrain_3d/bin/libterrain.web.debug.wasm32.nothreads.wasm"
web.debug.wasm32.nothreads = "res://addons/terrain_3d/bin/libterrain.web.debug.wasm32.nothreads.wasm"

Project Setup

Can be skipped with the default setup.

  • Web uses the Compatibility renderer which should be set automatically by export even if on vulkan on the desktop.

  • On the web Esc is captured by the browser, so in our demo/UI.gd we've set it to release the mouse with Backtick, or F12 depending on the version.

  • In 4.3, Textures must be imported VRAM Uncompressed. Our forced decompression is insufficient. This is not necessary for 4.4. If you have issues with your platform, try this.

  • In 4.3, Create an override shader with the following changes. This has already been done for the 4.4 builds of Terrain3D.

    • Change usampler2DArray _control_maps to sampler2DArray _control_maps
    • Wrap all texture or texelFetch calls using _controlmaps with floatBitsToUint(), e.g. control[0] = texelFetch(_control_maps, index[0], 0).r; -> control[0] = floatBitsToUint(texelFetch(_control_maps, index[0], 0)).r;
    • This should break the shader while editing, but look normal on PC when finished.

Exporting

  • Ensure you've downloaded the godot export templates and you can successfully export and run our demo on your PC.
  • On the Project/Export dialog, enable Advanced Options
  • Select custom template debug: web_dlink_nothreads_debug.zip, which I found here: C:/Users/Cory/AppData/Roaming/Godot/export_templates/4.3.stable/web_dlink_nothreads_debug.zip
  • Enable Extensions Support
  • Ensure Threads Support matches the terrain web binary, and custom template above.

Upload to Webserver

  • After export, the full package must be uploaded to a webserver. Itch or your own. That server must be configured with SharedArrayBuffer & Cross Origin Isolation.

  • In nginx this can be enabled with:

    location ^~ /terrain3d/ {
        add_header "Cross-Origin-Opener-Policy" "same-origin";
        add_header "Cross-Origin-Embedder-Policy" "require-corp";
    }
  • On Itch.io , edit game, find the Embed Options section and enable:

SharedArrayBuffer support - (Experimental) This may break parts of the page or your project. Only enable if you know you need it.
