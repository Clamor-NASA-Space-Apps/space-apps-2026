✨ New Features

Lookahead 2D

2d-lookahead.mp4

One of the most requested features is finally out for 2D scenes! Thanks to @Mustfa-IT, the addon now supports the ability to move the camera ahead of the target based on the direction it's going in, also known as lookahead. The feature is available in all 2D follow modes.

In short, it works by tracking the velocity of the followed target, where the faster it moves, the further ahead the camera will move ahead of it. This can be clamped with a maximum velocity value so the camera does not start flying off-screen no matter how fast the target is moving. Values for both the acceleration and deceleration can be set to determine how fast the camera reaches its lookahead position and returns to its original position when the target stops moving, respectively.

Lookahead can be applied to the X and Y-axis together or separately, with additional parameters to adjust for each axis.

Note

A 3D variant of lookahead is currently being tested and will be out in a future release.

  • Thanks @elvisish for the proposal (#228).
  • A big thanks to @Mustfa-IT for the overall implementation (#612).
  • And thanks to @BenjaTK (#160) and @audeck (#284) for their initial contributions, discussions, and effort on this feature, which paved the way for the release here.

Framed Follow 2D Refactor

The underlying logic system for the Framed Follow Mode has been rewritten for PhantomCamera2D.
The refactor should provide more stability, remove odd cases where the camera gets stuck outside the dead zone, and generally make the camera behave more as one would expect.

This only affects the addon's internal code, and so no project or scene changes are needed to make use of the new system.

Note

A refactor for Framed Follow for PhantomCamera3D is planned for a future release.

🌟 Improvements

  • Increased the default pyramid shape size for the SpringArm3D node when using Third Person Follow if no shape value has been applied. This should help prevent overly egregious cases of the camera clipping through geometry.
    • Thanks @TranquilMarmot for the PR (#560).
  • Dead Zone viewer should now be triggered and appear more consistently when switching between scene tabs in the editor.
  • Updated Third Person Follow to no longer unintentionally rotate around the target's z-axis.
    • Thanks @TranquilMarmot for the report (#553) and PR (#559).

🐛 Fixes

  • Resolved an issue with the Camera3D's Environment class reference in C# occasionally getting mixed up with the System namespace class with the same name.
    • Thanks @Scuas for raising the issue (#624).
  • Resolved an issue where the Priority Override UI could appear in the game window, despite being disabled at runtime.
  • Removed duplicate removal of PhantomCameraManager singleton in plugin.gd, which could lead to errors when the addon is deactivated from Project Settings.
  • Resolved an issue with using lambda functions with @export_tool_button in PhantomCamera3D.gd for the Align With View buttons (#627).
    • Thanks @mikest for the report (#626).
  • Resolved an output error log from happening if a scene change occurs with a PCam having no Tween Resource applied.
  • Prevented a warning log from being triggered if a non-physics target is selected.

✨ New Features

TweenDirector & TweenDirectorResource

tween-director.mp4

Called PhantomCameraTweenDirector, is a new node type that adds the ability to override tweens between specific PCams.

It works by using a new resource type called TweenDirectorResource, which has a property option for a tween resource along with two lists: one that checks where the PCam is tweening From, and another that checks what PCam is being tweened To.

If any of the entries of the From and To targets match, then the tween resource applied here will be used instead of the one applied on the To PCam.

More details on the documentation page.

  • Thanks @JosephStar318 for the suggestion (#575).

Manual Interpolation (PCamHost)

Is an additional option for the Interpolation Mode setting for the PCamHost, which makes the camera only update when requested using the newly added process() function from the PCamHost.

  • Thanks to @Scuas for the suggestion (#596).

More details on the documentation page.

🌟 Improvements

  • Removed additional unneeded scenes and scripts.
  • Redesigned PhantomCameraTween resource icon.
  • Camera2D/3D now has its top_level property set to true whenever it's following an active PCam and false when it isn't.

v0.9.4
6d2c5e9

Important

This version requires Godot 4.4 or later.

✨ New Features

Align with View (3D)

align-with-view.mp4

Another editor feature that enables a PCam3D's transform values to be aligned with the current viewport's position and/or rotation. It features a separate button for position and rotation and a unified one that aligns both properties at the same time (#600).

Note: It behaves similarly to the built-in functionality found at the bottom of the viewport menu in the top left.

Target Gizmo Line (3D)

target_gizmo.mp4

Allows the PCam3D to draw a line between itself and its Follow / Look At target. The intent of this feature is to help identify what exact position PCam3D is following / looking at (#603).

🌟 Improvements

  • The initial camera reposition jerkiness when starting a scene with a PCam should now be removed or greatly reduced in both 2D and 3D scenes.
    • Thanks @mak448a for raising this issue (#540).
  • Compositor is now exposed for PCam3D, adding better parity to Camera3D nodes.
    • Thanks @danbolt for the PR (#556).
  • Refactor of the C# implementation of GetActivePhantomCamera inside PCamHost.
    • Thanks @GabCoolDude for the PR (#571)
  • Changed property, method, and signal name from using String to StringName to avoid potential performance spikes when using the C# wrapper.
    • Thanks @GabCoolDude for the PR (#576).
  • Framed Follow now behaves as expected when the follow target is moving diagonally on the edge of the dead zone in 3D scenes.
    • Thanks @Merxon22 for raising the issue (#458)
    • and @Mustfa-IT for the PR (#577).
  • Added the ability to instantiate addon resources at runtime in C#.
    • Thanks @GabCoolDude for the PR (#570).

🐛 Fixes

  • Removed wobbling movement side effect when reloading a scene with having an initial active PCam that uses Framed Follow (#551).
    • Thanks @DylanTallchiefGit for raising the issue (#539).
  • Resolved a regression in v0.9.3 where Third Person Follow would apply additional rotation if its follow target rotated at runtime.
    • Thanks @TranquilMarmot for raising the issue (#553).
  • Minor positional fix for the 3D Tweening Example scene. Should prevent the collider tween trigger from happening on scene start.
  • Fixed a C# function name inconsistency with SetThirdPersonDegrees, it is now called SetThirdPersonRotationDegrees.
    • Thanks @GabCoolDude for the PR (#564).
  • Fixed a C# bug where up and up_target had their types swapped.
    • Thanks @BitiLope for the PR (#572).
  • Fixed an issue when using the C# wrapper when loading a new scene with the same PCam, where it would result in a crash a few minutes after the new scene had loaded due to C#'s garbage collection.
    • Thanks @RyanOldis for the report (#566)
    • and @GabCoolDude for the PR (#573).
  • Fixed an issue where you couldn't get or set properties' values to Camera3DResource when accessing (#581)
    • Thanks @BitiLope for raising the issue (#580).
  • Fixed an issue where if a second PCam has tween_on_load set to false it will not trigger a tween the first time it becomes active (#598).
    • Thanks @mikest for raising the issue (#526).
  • Fixed an issue where a PCam would only become active if it had a higher priority value. Now it changes if it's higher OR equal to the currently active PCam (#599).
    • Thanks @JustASquid for raising the issue (#568).
  • Fixed an issue with TileMapLayer interactions not working in the 2D example scenes for Godot 4.5 and newer.

🏅 New Contributors

  • @BitiLope made their first contribution in #572
  • @Mustfa-IT made their first contribution in #577
